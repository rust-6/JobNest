JobNest
Job Referral & Application Tracker
Product Requirements Document  |  Version 1.0  |  June 2025
1. Product Overview
JobNest is a full-stack web application that centralises job referral tracking, application management, and career analytics in one clean interface. The product eliminates the spreadsheet chaos that students and early-career professionals face when managing multiple simultaneous job hunts.

2. Problem Statement
Job seekers — particularly students and freshers — manage dozens of applications across multiple platforms simultaneously. Common pain points include:
No single source of truth for referral status, follow-up deadlines, and interview schedules
Missed follow-ups due to lack of reminders, directly reducing offer rates
No analytics to understand personal success patterns (e.g. which companies convert best)
Resume/cover letter versions scattered across email, Drive, and Downloads folders

6.4  Status Tracking & Timeline
Every status change is appended to an immutable status_history array on the referral document
Timeline view renders a vertical stepper with date, old status, new status, and optional note
Ghosted status is auto-suggested if no update for 21 days (configurable per user)

6.6  Reminders & Notifications
Users set a follow-up date per referral; a background job (cron) checks daily
Notification channels: in-app notification bell + email (Nodemailer / SendGrid)
Email digest option: daily or weekly summary of pending follow-ups
Users can snooze a reminder by 3 / 7 / 14 days from the notification
Implementation note: Use BullMQ (Redis-backed) for reliable job scheduling. Avoid cron-only approach to prevent missed runs on dyno restarts.
6.7  Document Management
Upload PDF or DOCX (max 5 MB per file, max 20 files per user in free tier)
Storage: Cloudinary with folder scoped per userId
Resume versions are labelled by user (e.g. 'SWE Resume v2') and reusable across entries
Delete from Cloudinary is permanent; user prompted with confirmation dialog
6.8  Analytics
Total applications over time (line chart — weekly buckets)
Status distribution (donut chart)
Top companies applied to (bar chart)
Conversion funnel: Applied → Interview → Offer → Selected
Average time between stages (response time analytics)
Charts built with Recharts. Data computed server-side and cached (5-min TTL) to avoid expensive aggregation on each page load.

10. Security Requirements
All passwords hashed with bcrypt (cost factor 12)
Refresh tokens stored as hash (SHA-256) in DB — raw token never persisted
HTTP-only, Secure, SameSite=Strict cookies for refresh token
CORS restricted to known frontend origin(s)
Input validation with Zod on all endpoints; errors return 400 with structured messages
File upload: validate MIME type server-side (not just extension); max 5 MB enforced
Rate limiting: 100 req/min per IP globally; 5 req/min on auth routes
OWASP Top 10 review before v1.0 release; automated scanning with npm audit CI gate
